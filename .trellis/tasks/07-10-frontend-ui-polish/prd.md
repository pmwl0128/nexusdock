# 优化前端界面布局与视觉

## Goal

在不改变后端契约、页面信息架构或核心操作流程的前提下，统一 Nexus 管理控制台的布局层级、卡片与控件视觉，并提升桌面端和移动端的可读性与操作舒适度。

## What I already know

* 前端是 React 19 + Vite 的单页控制台，源代码位于 `web/`。
* 全局 shell、总览与设置页面主要由 `web/src/App.tsx` 和 `web/src/nexus.css` 驱动。
* 现有设计是深色侧栏、浅色主内容区和靛蓝色状态强调；`nexus.css` 经过多轮追加，存在互相覆盖的同类布局规则。
* 项目规范要求保留操作控制台的信息密度，不添加新的后端 API，并在桌面和移动尺寸验证 `/ui/`。

## Requirements

* 对 Nexus 控制台做一次产品化的布局与视觉重塑，包括全局外壳、总览、运行时和工作流页面的视觉系统；不重构 Recall 业务交互。
* 可重新定义品牌颜色与氛围，不受当前深蓝紫配色限制；保持克制、专业、适合高密度运维控制台的可读性。
* 优化信息层级、间距、卡片、交互状态与响应式展示。
* 维持现有路由、数据请求、可访问性语义和现有操作入口。
* 不新增后端 API、图像资产或第三方运行时依赖。

## Decision (ADR-lite)

**Context**：现有页面经过多轮局部样式追加，虽能使用但整体识别度、层级和响应式一致性不足。

**Decision**：采用 Aurora 深色控制台外壳与浅色工作区的产品化方向，以青绿、蓝色和紫罗兰作为功能性强调色；采用单一 token 系统统一页面容器、面板、按钮、状态和断点。

**Consequences**：视觉改动覆盖面较大，但不改变数据模型和交互流程；需在桌面和移动端逐页回归检查，以防现有的页面专属 CSS 被新规则意外覆盖。

## Acceptance Criteria (evolving)

* [x] 桌面端控制台的侧栏、顶栏、内容容器和面板层级统一且可扫描，且拥有独立的产品化视觉识别。
* [x] 移动端导航与页面内容没有横向溢出、遮挡或不可达的操作。
* [x] `npm run build` 通过，并更新嵌入式 `internal/httpx/web_dist` 构建产物。
* [x] 浏览器验证覆盖 `/ui/` 的桌面及移动宽度，且没有新的控制台错误。

## Definition of Done

* 相关构建检查通过。
* 使用浏览器在关键断点完成视觉检查。
* 如有必要，记录本次发现的可复用规范。

## Out of Scope (explicit)

* 新增产品功能、后端接口、数据模型或认证流程。
* 改变 Recall 的业务逻辑或 Git 同步行为。

## Technical Notes

* 已检查：`web/src/App.tsx`、`web/src/nexus.css`、`web/src/styles.css`、`web/package.json`、`web/vite.config.ts`。
* 相关规范：`.trellis/spec/frontend/index.md`。
* 已在 1440px 宽度下打开 `/ui/`：总览、侧栏和主要卡片都能渲染；本地 Vite 代理没有后端服务，`/v1/auth/session` 返回 404，因此出现会话提示且记录一条资源加载错误。这不是前端构建错误，但完整认证态验证需要本地 Nexus 服务运行。
* 初步视觉问题：同一 CSS 文件存在多轮覆盖式补丁；桌面端的总览卡片密度偏低，主内容留白和标题层级不稳定；不同运行时页面的圆角、边框、阴影与工具栏尺寸没有统一的设计 token。
* 实施完成：增加 Aurora token 层，重塑深色侧栏、工作区背景、状态与用户控件、总览卡片、运行时和 Workflow 面板；保留现有数据流和操作入口。
* 浏览器回归：内置浏览器在 1440px 下确认总览正常渲染；在 390px 下确认无横向溢出，固定移动顶栏可用，`#/tasks` 路由可达，控制台错误为空。
* 验证命令：`npm run build`、`go test ./...`、`git diff --check` 均通过。
* Spec review：没有新增接口、跨层契约或可脱离当前视觉方案复用的工程约定；现有前端规范已覆盖 API 边界、构建产物和桌面/移动端浏览器验证，因此无需修改 `.trellis/spec/`。
